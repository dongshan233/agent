# P0-03 上下文工程与成本工程：把 token 当预算管

> P0 生产化深挖 · 模块 3 / 4。**前置**：P0-01 trace、P0-02 eval 门禁都已跑通并留了基线数据。
> 目标：在不掉完成率的前提下，把每任务 token 明显降下来，并**用 P0-02 的门禁证明它没掉**。

## 学习目标

1. 理解为什么 2026 年「上下文工程」取代了「提示词工程」
2. 实现四种优化：历史剪枝、滚动摘要、工具返回瘦身、模型路由 + 预算护栏
3. 知道剪枝时最容易踩的 API 硬约束（`tool_calls` 消息对必须完整）
4. 用 `CompositeHooks` 把 tracing 与预算护栏叠在一起，不改核心循环
5. 产出一张有前后数据的优化对比表，写进 README

---

## 1. 为什么（对照安卓）

一期第 5 周讲过上下文管理三原则（长窗口 ≠ 好用、Lost in the middle、主动剪枝），第 12 周把「历史剪枝 / 工具返回瘦身」列为**可选低成本优化**。二期把它从「可选」升为「主线」，原因是它同时决定三件事：质量、延迟、钱。

对照安卓，这套心智模型你本来就有：

| 安卓 | 上下文 / 成本工程 |
| --- | --- |
| 内存是硬预算，被动 OOM 不如主动 LRU | 上下文窗口是硬预算，主动剪枝 |
| `LruCache` / 图片采样 `inSampleSize` | 历史剪枝 / 工具返回瘦身 |
| 大图先压缩再加载 | 大的 tool 结果先摘要再回填 |
| 低端机走轻量渲染路径 | 简单意图路由到便宜模型 |
| 分级加载 / 按需 fetch | 动态上下文选择，而不是把整个 wiki 塞进去 |
| 电池 / 流量监控 + 硬上限 | 每会话 token 上限 + 成本告警 |

**2026 年的术语变化很重要**：`prompt engineering`（怎么措辞）已经让位于 `context engineering`（**在每一步，模型该看到哪些信息**）。大多数看起来像「模型不够聪明」的质量问题，追到 trace 里其实是上下文问题：该检索的策略文档没检索到、检索到了过期版本、历史里塞了太多无关内容把关键指令挤到了中间。

一句话：**给模型最少但最可信的信息，而不是最多。**

### 钱从哪来

一期第 4 周讲过：每轮都把完整历史重发一遍，输入 token 随轮次线性增长。P0-01 的 trace 现在让你能精确看到它：

```
turn1 prompt=210  →  turn2 prompt=340  →  turn3 prompt=380 ...
```

成本杠杆按收益排序（2026 生产实践）：

| 手段 | 典型收益 | 风险 | 本模块 |
| --- | --- | --- | --- |
| 模型路由（简单请求走便宜模型） | 40~85% 账单下降 | 路由判错 | ✅ |
| prompt caching（稳定 system 前缀） | 输入命中缓存后大幅降价 | 平台支持不一 | ✅ 讲做法 |
| 历史剪枝 / 滚动摘要 | 长会话 30~60% | 剪掉关键信息 | ✅ |
| 工具返回瘦身 | 大 JSON 场景 50%+ | 丢字段 | ✅ |
| 每会话 token 上限 | 防跑飞烧钱 | 误杀长任务 | ✅ |

## 2. 概念：四个优化点在一次循环里的位置

```
run_task 的 while 循环（一期第 6 周）
  │
  ├─ ① 进入每轮前：context_policy(history)   ← 剪枝 / 摘要
  │
  ├─ ② call_model(history, tools, model=...) ← 模型路由在这里选 model
  │       └── usage 回填 → BudgetHooks 累加 ← 预算护栏
  │
  ├─ ③ 执行工具，得到 out                    ← 工具返回瘦身（包装 tool_funcs）
  │
  └─ ④ history.append(tool 消息)              ← 回填的是瘦身后结果
```

四个优化点全部是**横切关注点**：一个走 `context_policy`，一个走 `model` 参数，一个走 `tool_funcs` 包装，一个走 `hooks`。**核心循环只加一行**（§3 步骤 1 的补丁），其余全在外面。这正是 P0-01 把 `hooks` 设计成 Interceptor 的回报。

### 步骤 2：`server/context.py`（剪枝 + 摘要 + 瘦身）

```python
"""server/context.py —— 上下文工程。全部是纯函数/包装器，不碰核心循环。"""
from __future__ import annotations

import json
import os
from typing import Any, Awaitable, Callable

from server.base import MODEL_FAST, call_model

ContextPolicy = Callable[[list[dict]], Awaitable[list[dict]]]


def split_groups(messages: list[dict]) -> tuple[list[dict], list[list[dict]]]:
    """按 user 消息把历史切成「轮组」。

    关键：assistant(tool_calls) 和紧跟其后的 tool 消息天然落在同一个组里，
    因为工具调用发生在 user 之后、下一个 user 之前。按组剪枝永远不会
    把 tool 消息和它的 assistant 拆开 —— 这是 OpenAI 兼容接口的硬约束。
    """
    system = [m for m in messages if m.get("role") == "system"]
    groups: list[list[dict]] = []
    cur: list[dict] = []
    for m in messages:
        if m.get("role") == "system":
            continue
        if m.get("role") == "user" and cur:
            groups.append(cur)
            cur = []
        cur.append(m)
    if cur:
        groups.append(cur)
    return system, groups


def prune_history(messages: list[dict], keep_last: int = 4) -> list[dict]:
    """保留 system + 最近 keep_last 轮。零成本、100% 确定。"""
    system, groups = split_groups(messages)
    if len(groups) <= keep_last:
        return messages
    kept = groups[-keep_last:]
    return system + [m for g in kept for m in g]


def _render_group(g: list[dict]) -> str:
    parts = []
    for m in g:
        role = m.get("role")
        if role == "user":
            parts.append(f"用户: {m.get('content')}")
        elif role == "assistant" and not m.get("tool_calls"):
            parts.append(f"助手: {(m.get('content') or '')[:200]}")
        elif role == "assistant" and m.get("tool_calls"):
            names = [tc["function"]["name"] for tc in m["tool_calls"]]
            parts.append(f"助手调用了: {', '.join(names)}")
        elif role == "tool":
            parts.append(f"工具结果: {(m.get('content') or '')[:150]}")
    return "\n".join(parts)


async def compact_history(messages: list[dict], keep_last: int = 4) -> list[dict]:
    """把被剪掉的旧轮次压成一条摘要 system 消息（用便宜模型，一次性成本）。"""
    system, groups = split_groups(messages)
    if len(groups) <= keep_last:
        return messages

    old, recent = groups[:-keep_last], groups[-keep_last:]
    old_text = "\n---\n".join(_render_group(g) for g in old)
    prompt = (
        "把下面的对话历史压缩成不超过 150 字的中文摘要，保留：用户偏好、"
        "已确认的事实、已做出的决定、未解决的问题。不要复述寒暄。\n\n"
        f"{old_text[:4000]}"
    )
    try:
        r = await call_model(
            [{"role": "user", "content": prompt}],
            model=MODEL_FAST, temperature=0,
        )
        summary = r.content.strip()
    except Exception as e:
        summary = f"（摘要生成失败，已按原样剪枝：{type(e).__name__}）"

    base_system = "\n".join(m.get("content", "") for m in system)
    merged = [
        {"role": "system", "content": f"{base_system}\n\n[历史摘要] {summary}"}
    ]
    return merged + [m for g in recent for m in g]


def slim_tool_result(text: str, limit: int = 800) -> str:
    """工具返回瘦身：优先保留 JSON 关键字段，否则直接截断并标注。"""
    if len(text) <= limit:
        return text
    try:
        data = json.loads(text)
        if isinstance(data, dict):
            keep_keys = ("city", "temp_c", "condition", "error", "matched",
                         "files", "items", "summary", "temp", "code", "message")
            kept = {k: v for k, v in data.items() if k in keep_keys}
            if kept:
                out = json.dumps(kept, ensure_ascii=False)
                if len(out) <= limit:
                    return out
    except (ValueError, TypeError):
        pass
    return text[:limit] + f"…[已截断 {len(text)}→{limit} 字符]"


def wrap_slim(funcs: dict, limit: int = 800) -> dict:
    """包装 tool_funcs，让每个工具结果在回填前自动瘦身。支持同步/异步工具。"""
    import asyncio

    out: dict = {}
    for name, fn in funcs.items():
        def make(f):
            async def wrapped(**kwargs):
                res = f(**kwargs)
                if asyncio.iscoroutine(res):
                    res = await res
                return slim_tool_result(str(res), limit)
            return wrapped
        out[name] = make(fn)
    return out


def make_context_policy(
    *, keep_last: int = 4, compact: bool = False
) -> ContextPolicy:
    """组装一个可传给 run_task(context_policy=...) 的策略。

    开关用环境变量，方便逐个优化做 A/B 而不改代码：
      CTX_PRUNE=1   开剪枝
      CTX_COMPACT=1 开滚动摘要（含剪枝）
    """
    async def policy(messages: list[dict]) -> list[dict]:
        if os.getenv("CTX_COMPACT") == "1" or compact:
            return await compact_history(messages, keep_last=keep_last)
        if os.getenv("CTX_PRUNE") == "1":
            return prune_history(messages, keep_last=keep_last)
        return messages
    return policy
```

> **剪枝的坑（务必记住）**：OpenAI 兼容接口要求 `assistant` 消息带 `tool_calls` 时，后面必须紧跟对应 `tool_call_id` 的 `tool` 消息，否则直接 400。所以**绝不能按「消息条数」粗暴切**。`split_groups` 按 user 分组就是为了从结构上保证消息对完整。面试讲这个细节，比讲「我做了上下文压缩」专业得多。

### 步骤 3：`server/cost.py`（路由 + 预算护栏 + hooks 组合）

```python
"""server/cost.py —— 成本工程。"""
from __future__ import annotations

import os
from typing import Any

from server.base import MODEL, MODEL_FAST, ModelResponse, AgentResult, estimate_cost

# 简单意图：不需要多步工具、上下文短 → 走便宜模型
SIMPLE_HINTS = ("你好", "几点", "翻译", "解释", "什么是", "一句话", "总结这句话")
COMPLEX_HINTS = ("比较", "然后", "再", "如果", "查一下", "先", "乘", "度")


class BudgetExceeded(Exception):
    """预算超限时抛出。run_task 的 try/except 会捕获它并写进 result.error。"""


def route_model(task: str, *, force: str | None = None) -> str:
    """静态路由：按任务特征选模型。

    生产里更常见的是动态路由（按每一轮的状态判断），但静态版
    零成本、可解释、够覆盖本项目 3 个场景，先把它跑通。
    """
    if force:
        return force
    if os.getenv("COST_ROUTE") != "1":
        return MODEL
    t = task.strip()
    if len(t) <= 20 and any(h in t for h in SIMPLE_HINTS) \
            and not any(h in t for h in COMPLEX_HINTS):
        return MODEL_FAST
    return MODEL


class BudgetHooks:
    """每轮累加 token / 成本，超限直接中断（靠异常，不用改循环）。"""

    def __init__(self, max_tokens: int = 6000, max_cost_yuan: float = 0.05):
        self.max_tokens = max_tokens
        self.max_cost = max_cost_yuan
        self.tokens = 0
        self.cost = 0.0

    async def on_model(self, r: ModelResponse, turn: int) -> None:
        self.tokens += r.usage.get("total_tokens", 0)
        self.cost += estimate_cost(r.usage)
        if self.tokens > self.max_tokens or self.cost > self.max_cost:
            raise BudgetExceeded(
                f"预算超限: tokens={self.tokens}/{self.max_tokens}, "
                f"¥{self.cost:.4f}/¥{self.max_cost}"
            )

    async def on_tool(self, name, args, out, turn, elapsed_ms) -> None:
        pass

    async def on_end(self, result: AgentResult) -> None:
        print(f"[budget] tokens={self.tokens} cost=¥{self.cost:.4f} "
              f"limit={self.max_tokens}/¥{self.max_cost}")


class CompositeHooks:
    """把多个 hooks 叠起来。P0-01 tracing + P0-03 budget 同时生效。"""

    def __init__(self, *hooks: Any):
        self.hooks = hooks

    async def on_model(self, r: ModelResponse, turn: int) -> None:
        for h in self.hooks:
            await h.on_model(r, turn)

    async def on_tool(self, name, args, out, turn, elapsed_ms) -> None:
        for h in self.hooks:
            await h.on_tool(name, args, out, turn, elapsed_ms)

    async def on_end(self, result: AgentResult) -> None:
        for h in self.hooks:
            await h.on_end(result)
```

**`BudgetExceeded` 为什么能中断循环**：P0-01 的 `run_task` 把整个 for 循环包在 `try/except Exception` 里。`on_model` 是 `await` 调用的，异常会沿调用栈冒到 `run_task` 的 except，写入 `result.error`，并照常执行 `finally` 里的 `hooks.on_end()` 落盘 trace。所以**预算护栏不用改一行循环代码**，且超限那次运行仍留完整 trace 供复盘。这是 hooks 设计的一个巧妙复用，值得自己跑一遍验证。

### 步骤 4：把优化装进主链路（改 `server/api.py` 与 `eval/run_eval.py`）

```python
from server.context import make_context_policy, wrap_slim
from server.cost import BudgetHooks, CompositeHooks, route_model
from server.observability import TracingHooks
from scripts.demo_tools import TOOL_FUNCS, build_tools   # 换成你的真实工具

policy = make_context_policy(keep_last=4)                # 进程级复用
guarded_tools = wrap_slim(TOOL_FUNCS, limit=800)

async def handle(req):
    hooks = CompositeHooks(
        TracingHooks(req.message, req.thread_id),
        BudgetHooks(max_tokens=6000, max_cost_yuan=0.05),
    )
    return await run_task(
        req.message,
        thread_id=req.thread_id,
        tools=build_tools(),
        tool_funcs=guarded_tools,
        model=route_model(req.message),
        hooks=hooks,
        context_policy=policy,
    )
```

### 步骤 6：prompt caching 与稳定前缀

多数 OpenAI 兼容平台会对**完全相同的长前缀**自动缓存并降价。条件只有一个：**system 前缀逐字节稳定**。所以：

- 一期 `SYSTEM` 常量不要每次拼时间戳、不要拼 `thread_id`、不要拼动态检索结果
- 动态内容（历史摘要、用户画像）放在 system 的**尾部**或单独一条消息，别插在开头
- 工具 schema 顺序固定（`build_tools()` 返回列表顺序不要随机）

如果平台支持显式缓存（如 Anthropic 风格），按官方文档在请求里加 `cache_control`，示意：

```python
# 仅示意，按你平台的文档为准，不要照抄到不兼容的接口
payload["messages"] = [
    {"role": "system", "content": [
        {"type": "text", "text": SYSTEM, "cache_control": {"type": "ephemeral"}}
    ]},
    *history[1:],
]
```

**验证方法**：跑两次相同任务，看 trace 里 `prompt_tokens` 和平台响应中是否有 `cached_tokens` / `prompt_cache_hit_tokens` 字段，把命中率记进优化表。

### 步骤 7：一键对比脚本（可选但好用）

`scripts/compare_runs.py`：

```python
"""scripts/compare_runs.py —— 对比两次 eval 的指标。
运行: uv run python scripts/compare_runs.py eval/baseline.json eval/last_run.json
"""
import json
import sys
from pathlib import Path

KEYS = ("task_success", "avg_tokens", "cost_per_task_yuan",
        "p95_latency_ms", "avg_turns", "safety_violations")


def main() -> None:
    a = json.loads(Path(sys.argv[1]).read_text(encoding="utf-8"))["metrics"]
    b = json.loads(Path(sys.argv[2]).read_text(encoding="utf-8"))["metrics"]
    print(f"{'指标':<22}{'基线':>12}{'现在':>12}{'变化':>12}")
    for k in KEYS:
        x, y = a.get(k, 0), b.get(k, 0)
        delta = f"{(y - x) / x * 100:+.1f}%" if x else "-"
        print(f"{k:<22}{x:>12}{y:>12}{delta:>12}")
    ok = (b["task_success"] >= a["task_success"]
          and b["safety_violations"] <= a["safety_violations"]
          and b["avg_tokens"] < a["avg_tokens"])
    print("\n结论:", "优化有效且质量未退步 ✓" if ok else "质量退步或没省下 token，需回滚 ✗")


if __name__ == "__main__":
    main()
```

把最终对比表贴进 README 的「成本」章节，配一句人话结论：「上下文剪枝 + 工具瘦身 + 模型路由后，每任务 token 从 812 降到 4xx，完成率维持 0.90」。**这比任何「我做了优化」的描述都有说服力**——一期第 12 周让你有成本意识，二期让你有成本数据。

## 4. 常见报错与修复

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| `400 ... tool_calls must be followed by tool messages` | 按消息条数剪枝，把 assistant(tool_calls) 和 tool 消息拆开了 | 用 `split_groups` 按 user 分组剪，见 §3 步骤 2 |
| 开剪枝后完成率掉了 | 剪掉了用户偏好 / 关键事实 | `keep_last` 调大；或开 `CTX_COMPACT` 保留摘要 |
| 开滚动摘要后反而更慢 | 摘要本身多一次模型调用 | 只在 `len(groups) > keep_last + 2` 时才摘要；或用更便宜的 fast 模型 |
| `BudgetExceeded` 后 trace 没了 | 以为异常会跳过 finally | 不会：`run_task` 的 finally 仍调 `on_end`；若真没有，检查 `CompositeHooks.on_end` 是否逐个调用 |
| 路由后答案明显变笨 | `SIMPLE_HINTS` 误判了复杂任务 | 路由规则加 `COMPLEX_HINTS` 否决；或对 `type=多工具` 的用例强制主模型 |
| `MODEL_FAST` 未配置 | `.env` 没加 | 加 `LLM_MODEL_FAST=...`；`route_model` 已有 fallback 到 `MODEL` |
| 平台报 `cache_control` 不支持 | 显式缓存是平台特性 | 去掉该字段，只保留「稳定 system 前缀」这一条通用做法 |
| 优化后 `results.md` 数据没变 | `run_eval.py` 还在用旧的 `run_task` 调用（没传 policy/hooks） | 按步骤 4 同步改评估入口，**门禁必须测优化后的链路** |
