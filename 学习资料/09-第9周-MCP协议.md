## 学习目标

1. 理解 Host / Client / Server 三角色架构
2. 掌握三大原语 Tools / Resources / Prompts 与两种传输方式
3. 用官方 Python SDK 写出自己的 MCP Server
4. 用 Inspector 调试后接入 LangGraph Agent

## 1. MCP 解决什么问题

回顾你目前的痛点：第 6~8 周的工具（calculator、weather、notes）都是**写死在 Agent 进程里的 Python 函数**。问题：

- 工具代码和 Agent 代码耦合，别的 Agent 想用得复制粘贴
- 工具可能是另一个语言/进程写的（比如跑在你手机上、或某台服务器上）
- 每家框架的工具接口格式不同

MCP 的答案：**把「工具能力」标准化成协议**。工具方实现一次 Server，任何支持 MCP 的 Host（Claude Desktop、IDE、你的 LangGraph Agent）都能接入。

对照安卓（非常贴切的类比）：

| 安卓 | MCP |
| --- | --- |
| App | Host（Agent 应用） |
| Binder / ContentProvider client | Client（Host 内的协议适配层） |
| ContentProvider / AIDL Service | Server（能力提供方） |
| URI + 契约 | 协议消息 |

## 2. 架构：三角色

```
┌───────────────────────┐
│ Host（你的 LangGraph Agent）  │
│  ┌────────────┐        │
│  │ MCP Client │────── 协议消息 ──────┐
│  └────────────┘        │          │
└───────────────────────┘          ▼
                          ┌──────────────┐
                          │ MCP Server（你的笔记/文件工具） │
                          └──────────────┘
```

- **Host**：最终用户使用的 AI 应用，管理多个 Client
- **Client**：Host 内部与一个 Server 的 1:1 连接封装
- **Server**：暴露工具/资源的小服务（一个进程）

**2026-07-28 版要点**：核心协议无状态——每个请求自包含，服务器不需要维护跨请求会话；取消了旧的 initialize 握手流程。这让 Server 更容易水平扩展（无会话亲和性要求），也更像你熟悉的普通 HTTP API。

## 3. 三大原语

| 原语 | 作用 | 类比 | 谁控制 |
| --- | --- | --- | --- |
| **Tools** | 模型可调用的操作（有副作用） | 函数调用 / POST 接口 | 模型决定何时调用 |
| **Resources** | 只读数据源（文件、记录） | GET 接口 / ContentProvider | 应用决定何时取 |
| **Prompts** | 预置的提示词模板 | 快捷短语/Intent 模板 | 用户主动触发 |

本周重点是 **Tools**（其余了解概念即可）。每个 Tool 的定义结构你应该眼熟：name / description / JSON Schema 参数——**和第 5 周你手写的 Function Calling schema 完全同构**。MCP 本质上是把 Function Calling 的工具定义层协议化了。

## 4. 两种传输方式

| 传输 | 场景 | 特点 |
| --- | --- | --- |
| **stdio** | Server 与 Host 同机（本地子进程） | Host 拉起 Server 进程，用 stdin/stdout 通信；零网络配置 |
| **Streamable HTTP** | 远程 Server（独立部署） | 普通 HTTP 请求，可挂鉴权、可多租户 |

本周用 stdio（本地练手），第 10 周架构设计时再考虑 HTTP。

## 5. 用官方 Python SDK 写 Server

安装：`uv add "mcp[cli]"`。

`week09/notes_server.py`：

```python
"""MCP Server：笔记查询 + 目录列表。用 FastMCP 定义工具。"""
import json
from pathlib import Path

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("notes-tools")        # Server 名字

NOTES_DIR = Path(__file__).parent / "notes"
NOTES_DIR.mkdir(exist_ok=True)


@mcp.tool()
def query_note(keyword: str) -> str:
    """按关键词搜索笔记，返回所有命中的笔记标题。当用户询问笔记内容相关问题时使用。"""
    hits = []
    for f in NOTES_DIR.glob("*.md"):
        if keyword.lower() in f.read_text(encoding="utf-8").lower() or keyword in f.stem:
            hits.append(f.stem)
    return json.dumps({"keyword": keyword, "matched": hits}, ensure_ascii=False)


@mcp.tool()
def read_note(title: str) -> str:
    """读取指定标题的笔记全文。必须先用 query_note 确认标题存在。"""
    path = NOTES_DIR / f"{title}.md"
    if not path.exists():
        return f"错误：笔记 {title} 不存在"
    return path.read_text(encoding="utf-8")


@mcp.tool()
def list_directory(path: str = ".") -> str:
    """列出 notes 目录下的文件名。"""
    entries = [p.name for p in (NOTES_DIR / path).iterdir()]
    return json.dumps({"files": entries}, ensure_ascii=False)


if __name__ == "__main__":
    mcp.run(transport="stdio")      # 本地 stdio 模式
```

注意三件事：

1. `@mcp.tool()` 同样从**类型标注 + docstring** 生成 schema——又是你在第 2、5、7 周练的那套，一套技能贯穿全程。
2. 工具返回**字符串**（通常 JSON）。错误也用字符串返回（「错误：…」），让调用方模型能读到，呼应第 6 周的异常回填原则。
3. 描述写清「何时用、如何用」（query_note 里写了「必须先确认标题存在」）——第 5 周的 schema 四原则原样适用。

## 7. 接入 LangGraph Agent（本周验收第二关）

LangGraph 已内置 MCP 客户端适配。要点：用 `MultiServerMCPClient` 配置 stdio Server，加载工具后挂到模型上。

`week09/mcp_agent.py`：

```python
"""用 MCP Server 的工具跑 LangGraph Agent。"""
import asyncio

from langchain_mcp_adapters.client import MultiServerMCPClient   # uv add langchain-mcp-adapters
from langchain.chat_models import init_chat_model

from graph_agent import build_app        # 第7周的图构建函数（工具改为注入）


async def main() -> None:
    client = MultiServerMCPClient({
        "notes": {
            "command": "uv",
            "args": ["run", "notes_server.py"],
            "transport": "stdio",          # Host 负责拉起 Server 子进程
        }
    })
    tools = client.get_tools()             # 返回 LangGraph 兼容的工具列表

    llm = init_chat_model("openai:gpt-4o-mini").bind_tools(tools)
    app = build_app(llm, tools)            # 第7周的 StateGraph，模型与工具从外部注入

    result = await app.ainvoke(
        {"messages": [("user", "帮我找找有没有关于日程的笔记，有的话读出来总结")]},
        config={"configurable": {"thread_id": "mcp-demo"}},
    )
    print(result["messages"][-1].content)

asyncio.run(main())
```

完整链路验证：用户提问 → 模型发起 `query_note` → **MCP Client 经 stdio 发给你的 Server 进程** → 结果回填 → 模型再发起 `read_note` → 总结回答。

跑通后对照思考：你的 Agent 代码里已经**看不到任何工具实现了**——calculator 是本地的，笔记工具在另一个进程里，但对模型和图完全透明。这就是协议化的价值。
